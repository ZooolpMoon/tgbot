# 📚 知识库（RAG）

[返回首页](../README.md) · [文档索引](README.md)

给 AI 加上「先查资料再回答」的能力：管理员上传群规、产品手册、FAQ，用户提问时机器人先检索，命中就依据资料作答并标注来源。

```
群成员：@YourBot 退货怎么处理？
Bot  ：检索本群 + 全局知识库 → 命中「售后政策」→ 依据资料回答并标注来源
```

---

## 作用域

| 打开位置 | 作用域 `scope_key` | 谁能检索到 |
|----------|--------------------|-----------|
| 群里 `/kb` 或群里的管理面板 | `group:<群ID>` | 只有这个群 |
| 私聊 `/kb` 或私聊的管理面板 | `global` | 所有私聊与群聊 |

检索时**本群资料 + 全局资料一起参与**，按相似度排序取前 4 条（最多 2000 字）拼进提示词。

> 群知识库用的是「群级」键（`group:<群ID>`），不是成员级场景键——否则只有上传者本人能检索到。

## 添加资料

两种方式：

1. **面板引导**：`/kb → ➕ 添加文档` → 输入标题 → 粘贴正文
2. **直接发文件**给机器人（管理员私聊，或在目标群里发并 @ 机器人）：

| 格式 | 解析方式 |
|------|---------|
| `.txt` `.md` `.markdown` `.csv` `.json` `.log` `.yml` `.yaml` | 直接按 UTF-8 解码 |
| `.docx` | 解 zip 取 `word/document.xml`，剥标签还原段落 |
| `.pdf` | 尽力抽取文本层；扫描件 / 加密文档会明确提示改用 OCR |

上传时会立刻切块并生成向量（几秒钟）。

## 文档管理

| 操作 | 说明 |
|------|------|
| 📄 文档列表 | 显示标题、分块数、来源、更新时间；点进详情可分页查看 |
| 🚫 / ✅ 启停 | 停用的文档不参与检索，内容保留 |
| 🗑️ 删除 | 二次确认后连同分块一起删除，**不可恢复** |
| ⬆️ 设为全局 | 把群文档提升为全局文档（所有场景可见） |
| ⬇️ 复制到本群 | 把全局文档复制一份到当前群（正文与向量一起复制） |
| 🔍 检索测试 | 输入一个用户可能会问的问题，查看命中资料与相似度评分 |
| 🧠 重建索引 | 补齐缺失向量或按新模型重建（每次 40 块，定时任务每次 20 块） |

## 技术细节与限制

| 项 | 值（都在 `src/config/constants.js` 的 `KB` 里） |
|----|------|
| 分块 | 按空行分段，段落超长按 600 字硬切，相邻块重叠 80 字 |
| 单文档上限 | 400 块 / 20 万字 / 文件 512 KB |
| 单作用域上限 | 400 块（超出会拒绝入库并提示精简） |
| 向量模型 | Workers AI `@cf/baai/bge-m3`（1024 维，多语言），可用 `KB_EMBED_MODEL` 覆盖 |
| 向量存储 | `kb_chunks.embedding` = base64 编码的 Float32Array，另存 `model` 记录生成它的模型名 |
| 检索 | 问题向量化后与库内向量算余弦相似度，阈值 0.30；再叠加关键词（中文二元字组）命中加成 |
| 相关度门槛 | 综合分 ≥ 0.45 视为强相关；**低于 0.45 时必须有真实关键词重叠**才会被采用，避免「沾边但不相关」的资料被拼进提示词 |
| 降级 | 未绑定 Workers AI 时自动改用关键词检索（阈值 0.12），功能不失效 |

## 回答模式

检索命中后，机器人会把资料和「回答要求」一起交给模型。**资料没覆盖的问题该怎么答**，由回答模式决定：

| 模式 | 行为 | 适用场景 |
|------|------|---------|
| `hybrid`（默认） | 资料能回答就优先依据资料并标注来源；**资料没覆盖时用 AI 自己的知识正常回答**，不会因为「资料里没写」就拒绝 | 群助手、日常问答（推荐） |
| `strict` | 只依据资料回答，资料里没有就明说「资料中未提及」，不补充外部知识 | 客服式严格问答、只允许按手册回答 |

切换方式：

```toml
[vars]
KB_ANSWER_MODE = "strict"     # 默认 hybrid，不填即为 hybrid
```

两种模式都要求：**只能标注真实存在的资料标题，禁止编造来源**；没有引用资料时不要写「— 摘自《…》」。

> 如果发现机器人回答「资料中未提及」却又编了个出处，通常说明注入的资料其实与问题无关——本项目已经用「相关度门槛」把这种资料挡掉，并让模型在资料不相关时正常作答。

## 检索测试怎么用

面板里的「🔍 检索测试」会把**所有候选**（包括被门槛挡掉的）列出来，并给出两个分数：

| 分数 | 含义 |
|------|------|
| 综合分 | 余弦相似度 + 0.15 × 关键词命中，最终排序依据 |
| 关键词 | 中文二元字组重合度（0~1），用于判断是否真的有字面重叠 |

调试建议：

- 有候选、综合分很低 → 资料与问法差异大，可以在文档里补充同义表述
- 没有候选 → 文档没启用、作用域不对，或者问的问题压根不在资料范围内（这时会走 AI 自己的知识回答）

### 为什么把向量存在 D1

这样只需要 D1 + Workers AI 两个绑定，不必额外开通 Vectorize。代价是检索时要把候选向量读进内存计算，所以对单作用域块数设了上限（默认 400 块，约 20 万字），足够放群规、产品手册这类资料。

规模更大时可以把 `src/services/knowledge.js` 的 `searchKnowledge` 换成 Cloudflare Vectorize 查询，其余调用方无需改动。

## 常见问题

<details>
<summary><b>检索不到内容</b></summary>

1. 文档是否处于「✅ 参与检索」（停用的不参与）
2. 作用域是否对：本群资料只在那个群可见；想让所有群都能用，点「⬆️ 设为全局」
3. 相似度不够：用「🔍 检索测试」看评分，分数太低说明资料与问法差异大，可以补充同义表述
4. 上传时没绑定 AI → 向量为空：点「🧠 重建索引」补上

</details>

<details>
<summary><b>换了向量模型之后</b></summary>

旧向量的维度与新模型不一致会被跳过，需要点「🧠 重建索引」分批补建（面板每次 40 块）。重建完成后新旧资料都能正常检索。

</details>

<details>
<summary><b>PDF 解析不出来</b></summary>

纯 JS 解析 PDF 只能尽力抽取**文本层**：扫描件（图片版）、加密文档、特殊字体编码都可能抽不出文字。机器人会明确提示，不会静默失败——用 OCR 转成文本后重新上传即可。

</details>
