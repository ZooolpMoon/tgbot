# 👑 管理后台导览

[返回首页](../README.md) · [文档索引](README.md)

入口：私聊发 `/admin`（只有 `MY_TELEGRAM_ID` 能用）。解锁状态 30 分钟有效，之后点击面板里的按钮会自动续期。

```
👑 管理控制台
├── 👥 用户管理
│   ├── 💬 私聊用户        → 用户列表 → 场景编辑 → 📇 用户详情
│   ├── 👥 群组用户        → 群列表 → 群成员 → 场景编辑
│   └── 🚫 封禁名单        → 一键解封
├── 📚 知识库              → 添加文档 / 文档列表 / 检索测试 / 重建索引
├── 📜 群规执法            → 编辑群规 / 群规历史 / 默认处置 / 默认禁言 / 预警 / 处置记录
├── 👑 管理员与权限        → 引导式增删管理员 / 改角色（**仅拥有者可见**）
├── 🛒 商城管理            → 商品列表 / 添加商品 / 待处理订单 / 全部订单
├── 🎟️ 兑换码              → 生成 / 启停 / 列表
├── ⚙️ 功能开关            → 全局 / 群聊场景 / 私聊场景 三级
├── 🗑️ 自动删除            → 按消息类型设置保留时长（全局 / 本场景）
├── 📋 操作日志            → 按 用户 / 商城 / 执法 / 知识库 / 功能开关 / 系统 筛选
├── 📊 运行状态            → D1 / Workers AI 绑定情况
├── 📈 使用统计            → 用户数、活跃场景、签到、积分总量…
└── 🧹 清空我的记忆
```

每个面板都用按钮操作，**不需要记指令**。

## 👑 管理员与权限

只有**拥有者**（环境变量 `MY_TELEGRAM_ID`）能看到这个入口。

| 角色 | 能力 |
|------|------|
| 👑 拥有者 | 全部，含「管理员与权限」本身 |
| 🛡️ 管理员 | 用户管理、商城、知识库、群规配置、功能开关、自动删除、兑换码、群发、日志与统计、执法；**不能**增减管理员 |
| ⚔️ 执法员 | 只能执法（封禁 / 踢出 / 禁言 / 群规查看 / 处理举报与申诉），不能进后台 |

操作方式：

- **➕ 添加管理员**：引导式三步——输入对方**数字 ID** → 选角色 → 填备注（回复 `-` 跳过）。已经是管理员的会提示「将覆盖角色」
- 点列表里的某个人 → 可以 **🔁 改角色** 或 **🗑️ 移除**（移除要二次确认）
- 拥有者自己不在这张表里，**也移不掉**（ID 来自环境变量）
- 每次变更都写审计日志（`admin_add` / `admin_update` / `admin_remove`）

> 小提示：加完人之后私聊他一句「先发 `/admin` 解锁」，否则他打开控制台会被提示「请先输入 /admin 解锁控制台」。

## 用户管理

| 面板 | 能做什么 |
|------|---------|
| 💬 私聊用户 | 分页浏览所有私聊场景 |
| 👥 群组用户 | 先选群（显示群 ID 与人数）→ 看该群成员 → 点进成员 |
| 场景编辑 | 改积分、看流水、调每日额度与冷却、开关功能、封禁 / 解封、清空记忆、删除场景（二次确认） |
| 📇 用户详情 | 一屏聚合：身份、积分、封禁状态、签到（累计 / 连续）、今日消息量、最近 3 条积分流水、最近 3 笔订单、最近 3 次群内处置 |
| 🚫 封禁名单 | 列出所有被封禁用户，一键解封；**机器人管理员不会出现在名单里**（三层面板都拒绝封禁自己） |

**积分与封禁是用户级的**（跨场景共享），其余配置都是场景独立的。

## 功能开关

7 项能力可独立开关，且是**三级**的：

| 层级 | 作用范围 |
|------|---------|
| 🌍 全局设置 | 所有私聊与群聊的默认值 |
| 👥 群聊场景 | 只影响某个群（不设置则跟随全局） |
| 💬 私聊场景 | 只影响某个用户（不设置则跟随全局） |

可开关项：

| key | 名称 | 影响范围 |
|-----|------|---------|
| `ai` | AI 对话 | 私聊 / 群聊里的 AI 回复 |
| `kb` | 知识库检索 | AI 回答前是否检索知识库 |
| `guard` | 群规执法 | 处置 / 举报 / 申诉指令、预警 |
| `game` | 游戏大厅 | 骰子、老虎机、硬币、转盘 |
| `checkin` | 每日签到 | 连续签到奖励 |
| `shop` | 积分商城 | 商品浏览与兑换 |
| `redeem` | 兑换码 | 用兑换码领积分 |

生效顺序：**场景显式设置 → 全局设置 → 默认开启**。关掉后指令、按钮回调、AI 回复都会被拦下并给出提示，不会留下半截状态；场景页支持「🔄 全部恢复跟随全局」。

## 🗑️ 消息自动删除

群聊里机器人自己发的消息，可以按**消息类型**分别设置保留多久（**0 秒 = 不删除**）：

**🌍 全局兜底（最长保留时间）**：面板最上面的一项，是**最高优先级的兜底**

- 分类型的设置照常生效（该 5 秒删的仍然 5 秒删）
- 到了兜底时间，机器人**所有**还没被删的消息一律删除（含 AI 回复、确认卡片、公告）
- 实际删除时间 = 「该类型自己的时长」与「兜底上限」里**更早**的那个
- 可选 `未设置 / 30 分钟 / 1 小时`；**只对设置之后发出的消息生效**（不追溯）
- 长延时由定时任务执行（cron 每 2 分钟扫一次），误差约 ±2 分钟

| 类型 | 默认 | 覆盖的消息 |
|------|------|-----------|
| ⚙️ 指令回执 | 5 秒 | 指令结果、用法提示、错误提示 |
| 🛡️ 执法回执 | 5 秒 | 封禁 / 踢出 / 禁言的结果提示 |
| 🖲️ 确认卡片 | 保留 | 需要留时间点击的处置 / 申诉卡片 |
| 🤖 AI 回复 | 保留 | 群聊里 AI 的回答 |
| 📢 系统通知 | 保留 | 处置公告、到期提醒与每日概况 |

设置同样分两级：**本场景** 优先于 **全局默认**，面板上可一键「跟随全局 / 恢复内置默认」。
群聊里改的是「这个群」（群内所有成员共享一份设置，不是每个成员一份）；
私聊消息本来就不删，定时推送如果发到群里也会按「系统通知」处理。

## 兑换码

- `/code_new <积分> [次数] [有效天数]`：次数 0 = 不限，天数 0 = 永久
- 每个码**每人限兑一次**（数据库唯一约束保证）；可随时停用 / 启用
- 列表页展示面额、已用 / 总次数、状态与过期日

## 群发通知

- `/broadcast <内容>` → 二次确认 → 分批发送给所有**未被封禁且私聊过机器人**的用户
- 分批写入进度游标，单次时间预算用尽会提示「继续发送」，支持断点续发
- 正文按纯文本推送（不解析 HTML），最长 3500 字符

## 操作日志（审计）

所有管理动作都会写入 `admin_logs`，支持按类别筛选，翻页时保留筛选条件：

| 筛选 | 包含的动作 |
|------|-----------|
| 👥 用户 | 封禁 / 解封、调整积分、调限额 / 频率、删除场景、清空记忆 |
| 🛒 商城 | 商品增删改与上下架（含发放方式与背包用法）、订单完成 / 取消退款 / 已完成订单退款 |
| 🛡️ 执法 | 发起 / 执行 / 取消处置、撤销、申诉处理、群规变更与开关 |
| 📚 知识库 | 文档新增 / 启停 / 删除、范围调整 |
| 🧩 功能开关 | 全局 / 场景开关的切换与恢复默认 |
| ⚙️ 系统 | 兑换码生成与启停等其它动作 |

## 🖥️ Web 管理后台（v3.10.0）

入口：**私聊**里发 `/web`，机器人回一条 5 分钟有效的一次性链接，点开即登录。

### 为什么不是 Telegram Login Widget

Login Widget 要在 BotFather 里配置域名，换域名（或从 `workers.dev` 换成自定义域名）就得重新配，
配错了就是「登不进去」而且很难自查。一次性链接没有这个问题：
生成端本来就在 Telegram 里，**能生成链接的人本来就是管理员**，鉴权面反而更小。

### 登录与会话

| 环节 | 做法 |
|------|------|
| 令牌 | 24 字节随机串，存 `web_login_tokens`，**5 分钟有效 + 用过即删** |
| 会话 | HMAC-SHA256 签名的 HttpOnly + Secure + SameSite=Strict cookie，12 小时 |
| 授权 | **每个请求都重新查一次角色** —— cookie 有效不代表还是管理员，撤权立即生效 |
| 密钥 | `WEBHOOK_SECRET`，没配则退回 `BOT_TOKEN` |

### 能做什么

| 标签页 | 内容 |
|--------|------|
| 📊 概览 | 用户数、群组数、积分总量、已封禁、待处理订单、近 7 天 AI 调用 / 失败 / 群消息 |
| 👥 用户 | 搜索（昵称 / 用户名 / 用户 ID / 群 ID）、封禁与解封、增减积分、分页 |
| 📜 日志 | 审计日志（时间 / 操作人 / 动作 / 详情），分页 |
| ⬇️ 导出 | 用户 CSV（最多 5000 行，带 BOM，Excel 打开不乱码） |

### 权限

和指令侧**完全一致**：写操作复用同一批函数（`banUserById` / `unbanUserById` / `resolvePointTarget`），
所以「不能封禁机器人管理员」这类兜底在 Web 上同样成立。
`⚔️ 执法员`能进后台，但改不了积分、封不了人（会被 `forbidden` 挡下）。

Web 上的写操作会在审计日志里留下 `web:<管理员ID>` 作为操作人，和 Telegram 侧的操作区分开。

### 地址从哪来

链接的域名取自 `WEBHOOK_URL`，没配则用「上一次通过 secret 校验的请求 origin」
（见 [部署与运维](deployment.md) 的 webhook 自愈一节）。两者都没有时会明确提示怎么补，
而不是给一个打不开的链接。
