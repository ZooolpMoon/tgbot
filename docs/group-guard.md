# 🛡️ 群规执法

[返回首页](../README.md) · [文档索引](README.md)

管理员在群里用**指令**下达处置；机器人**先校验理由，再让管理员确认**，最后才执行。

> 处置只认 `/指令`：自然语言里的「封禁」「拉黑」「踢了」太常见，
> 机器人不会去猜这些词，避免把正常聊天误当成执法指令。

```
/ban 发广告刷屏                 → 机器人封禁（回复对方消息后直接用；私聊 + 所有群停止服务）
/ban @某人 发广告刷屏            → 同上，直接点名
/mute @某人 2小时 辱骂他人        → 群内限时禁言
/kick @某人 发诈骗链接            → 踢出群组（可重新加入）
/groupban @某人 发广告            → 群内封禁（不可重新加入）
/unban @某人                     → 解除机器人封禁 + 群封禁
```

## 前置条件

把机器人拉进群，并设为**管理员**，至少勾选：

- 删除消息
- 封禁用户

缺少权限时，踢出 / 群封 / 禁言会被明确拒绝（不会静默失败）；「机器人封禁」不需要群管理权限。

## 指认对方的三种方式

| 方式 | 示例 | 说明 |
|------|------|------|
| 回复对方消息 | 回复违规消息 → `/ban 发广告` | **最可靠，推荐** |
| @用户名 | `/ban @someone 发广告` | 对方需与机器人交互过（否则机器人查不到 ID） |
| 用户 ID | `/mute 123456789 2小时 刷屏` | 可从「用户管理 → 群组用户 → 群成员」里看到 |

## 理由校验（三层）

**理由必须能对应到违规现象，否则不执行**。校验顺序：

1. **内置违规类型关键词**

   | 类型 | 关键词示例 |
   |------|-----------|
   | 广告 / 推广引流 | 广告、推广、引流、拉人、加我、刷单 |
   | 刷屏 / 灌水 | 刷屏、灌水、重复发、霸屏 |
   | 辱骂 / 人身攻击 | 辱骂、骂人、人身攻击、歧视 |
   | 骚扰 / 私聊骚扰 | 骚扰、纠缠、威胁、恐吓 |
   | 色情 / 低俗内容 | 色情、涉黄、低俗、擦边 |
   | 诈骗 / 赌博 / 违法 | 诈骗、骗钱、赌博、外挂、代练 |
   | 违规链接 / 不明文件 | 链接、外链、木马、钓鱼 |
   | 泄露隐私 / 人肉 | 隐私、人肉、开盒、身份证 |
   | 政治敏感 / 暴恐 | 政治、敏感、暴恐、煽动 |
   | 恶意刷群权益 / 打扰管理 | @全体、捣乱、不服从管理 |

2. **本群群规文本**（`/setrules` 写入，按句子做二元字组相似度比对）
3. **本群知识库**（群规是上传的文档时，走知识库检索）

三层都不命中就拒绝执行，并回复「可识别的违规类型 + 本群群规摘要」。被拒绝的尝试也会入库留痕。

## 两种处置通道

| 通道 | 效果 | 需要的权限 | 可撤销 |
|------|------|-----------|:------:|
| 🚫 机器人封禁 | 写 `users.blocked`，该用户在私聊与所有群都不再被服务 | 无 | ✅ |
| 👢 踢出群组 | 移出本群，可通过邀请链接重新加入 | 机器人须为本群管理员且能「封禁用户」 | ✅ |
| 🔨 群内封禁 | 移出且不能重新加入，**并删除该用户在本群的消息** | 同上 | ✅ |
| 🔇 群内禁言 | 限制发言，支持时长 | 同上 | ✅ |

支持的禁言时长：`10 分钟` / `30 分钟` / `1 小时` / `2 小时` / `1 天` / `永久`；也可以直接在指令里写任意时长，如 `90分钟`、`3天`、`永久`。

## 确认卡片

校验通过后机器人会发一张卡片，包含对象、处置、理由、依据：

```
🛡️ 群规执法 · 待确认
👤 对象：@某人（123456789）
⚖️ 处置：🚫 机器人封禁
📌 理由：发广告刷屏
📜 依据：广告 / 推广引流（违规类型「广告」）

[✅ 确认执行] [❌ 取消]
[改为群内禁言] [改为踢出群组]
[改为机器人封禁] [改为群内封禁]
```

- 只有**发起人本人**或**机器人管理员**能点确认
- 不能把管理员自己列为处置对象
- 确认后才真正调用 Telegram / 写封禁状态

## 引导式配置（`/guard` 面板）

```
📜 群规执法
├── 📝 编辑群规       → 发一段文字覆盖现有群规
├── ➕ 追加一条       → 追加到群规末尾
├── 🕘 群规历史       → 查看历史版本并一键回滚
├── 🧹 清空群规
├── ⚖️ 默认处置       → 机器人封禁 / 踢出 / 群内封禁 / 禁言（下指令没指明时用它）
├── ⏱️ 默认禁言时长   → 10分钟 / 30分钟 / 1小时 / 2小时 / 1天 / 永久
├── 🔔 预警开关
├── 🔑 预警关键词     → 自定义，或恢复内置词库
├── ✅/🚫 执法开关     → 一键启停本群执法
└── 📜 处置记录       → 含一键撤销
```

引导期间在群里**直接发文字即可（不需要 @ 机器人）**，30 分钟不操作自动失效，随时 `/cancel` 放弃。

## 主动预警（静默）

开启后，群成员发言命中关键词时：

```
成员：这个兼职日赚500，加微信了解
机器人：群里不发声；私聊管理员一张卡片（关键词 + 原话 + 确认处置按钮）
管理员：看一眼原话，决定「确认执行」或直接忽略
```

- 同一用户 10 分钟内只提醒一次，避免刷屏
- **群规对所有人一视同仁**：owner、机器人管理员、群管理员发言同样预警（v3.1.2 起；以前这几种身份会被跳过，导致「自己发预警词机器人没反应」）
- 目标是机器人管理员时会照常提醒，但卡片会写明「确认按钮会被安全策略拦下」——不允许把管理员封禁 / 禁言，否则会把后台访问权限一起锁掉
- 预警只产生 `pending` 记录，不产生任何公开处置

内置预警关键词：`加微信`、`加VX`、`私聊我`、`推广`、`代购`、`优惠券`、`兼职`、`刷单`、`返利`、`博彩`、`彩票`、`赌场`、`外挂`、`代练`、`翻墙`、`点击链接`、`http://`、`https://t.me/`、`免费领取`、`薅羊毛`、`引流`、`拉群`、`日赚`、`月入`。

## 成员举报

普通成员也可以参与治理，但**不会直接造成处置**：

```
成员：（回复违规消息）/report 发广告
Bot ：校验理由 → 通过则把带按钮的卡片发到管理员私聊，群里回执「已转给管理员」
管理员：在私聊里点「✅ 确认执行」（或改成禁言 / 踢出 / 群内封禁）
Bot ：在群里执行并公告结果
```

必须先**回复违规的那条消息**，举报才受理（否则不知道该处置谁）。
理由对不上群规时，机器人会让成员补充说明，不会打扰管理员。

## 处置到期与撤销

- **到期通知**：限时处置到期时，群里公告「处置已到期」，并私聊当事人「限制已解除」（Telegram 侧本来就自动解除，这里补齐可见性）
- **一键撤销**：处置记录页每条可撤销记录都有「↩️ 撤销」，会解除机器人封禁 + 群内限制、公告并私聊当事人，状态记为 `revoked`

## 申诉

被处置人可以私聊机器人发起申诉：

```
/appeal 我那是正常讨论，不是刷屏
```

申诉同样只认指令（群里发 `/appeal` 会提示去私聊）。

- 只能对**最近 7 天内、作用在自己身上**的处置发起申诉
- 同一处置重复申诉会被拦下
- 机器人把申诉卡片发到管理员私聊：
  - `✅ 撤销处置` → 解除限制 + 群里公告 + 私聊告知申诉人
  - `❌ 驳回申诉` → 通知申诉人「未通过」，原处置不变

## 群规版本历史

每次修改群规都会自动留一个版本（`/guard → 🕘 群规历史`），可以看到版本号、字数、修改时间与内容预览，并一键回滚到任意历史版本。回滚本身也会记一条新版本，历史不会丢。只改「默认处置」「默认禁言时长」不会产生无意义的版本。

## 权限与审计

| 项 | 规则 |
|----|------|
| 谁能下达处置 | 机器人管理员，或本群管理员（creator / administrator） |
| 谁能确认卡片 | 发起人本人，或机器人管理员 |
| 谁能处理申诉 | 机器人管理员，或原处置所在群的管理员 |
| 审计 | 所有请求（含被拒绝的）写入 `group_punishments`：对象、动作、理由、依据、时长、到期时间、操作人、状态 |

状态取值：`pending` 待确认、`done` 已执行、`cancelled` 已取消、`rejected` 理由不成立、`failed` 执行失败、`expired` 已到期、`revoked` 已撤销。

## 安全设计说明

「自动执法」最怕误伤，所以做了四道约束：

1. **必须给理由**，且理由要对得上群规 / 违规类型
2. 破坏性动作一律**先弹确认卡片**（可改处置方式）
3. 只允许管理员发起，且**不能对自己**下达处置
4. 全过程**入库审计**，可追溯、可撤销、可申诉

如果希望「理由通过就直接执行、不点确认」，可以改 `src/admin/guard.js` 的
`requestPunishmentFromCommand`（在 `requestPunishment` 之前直接调 `executePunishment`）——但一般不建议，除非群规写得非常明确。

## 相关：消息自动删除

执法回执默认 **5 秒后自动删除**（避免刷屏），确认卡片与处置公告默认保留。
这些都可在「管理控制台 → 🗑️ 自动删除」里按消息类型分别调整，见
[管理后台导览](admin-console.md#-消息自动删除)。
